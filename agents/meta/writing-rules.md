# Написання правил агентів

## Мова

Усі файли в `agents/` (включно з цим) — **українською**.

Дозволено англійською лише:

- ідентифікатори коду, шляхи файлів, імена типів, функцій, подій рушія
- рядки коду й команди (`claude plugin test .`)
- цитати повідомлень користувача іншими мовами як тригери

## Структура

- Один concern — один файл (або підпапка, якщо файлів кілька).
- Ім’я файлу/папки — `kebab-case` латиницею.
- Без дублювання тієї ж норми в кількох файлах: одне місце — одне правило; інші лише посилаються.
- Новий файл правил — рядок в індексі `agents/README.md` («тема → коли читати → шлях»).

## Стиль

- Коротко, імперативно, з прикладами ✅/❌ де корисно.
- Лише конкретика цього проєкту: шляхи, типи, патерни, факти з коду. **Не** додавати загальні фрази без проєктного змісту («ти — senior-розробник», «пиши ідіоматичний код», «дотримуйся best practices») — вони не змінюють поведінку агента, лише займають контекст.
- Твердження про код (константи, кількість місць, наявність патерну) — лише перевірені в коді на момент написання.
- Посилання на інші правила — відносними шляхами від кореня репо (`agents/...`).

## Адаптери

- `CLAUDE.md` у корені містить лише `@AGENTS.md`, щоб Claude Code підхопив правила. Канон туди не дублювати.
- Те саме для інших інструментів (`.cursor/rules` тощо), якщо колись знадобляться: лише вказівка на `AGENTS.md` / `agents/`.

## При конфлікті між правилами

Не «вирішувати мовчки». Зупинитись і запитати користувача (див. `agents/README.md`).
