# Правила агентів iso-office

Цей каталог — **єдине джерело правди** для правил агентів у цьому репозиторії.

## Обов’язки агента

1. Прочитати цей файл на початку роботи з репозиторієм.
2. Прочитати файли з підпапок, що стосуються поточної задачі (див. індекс нижче).
3. Не вигадувати правила з інших тул-специфічних місць — канон лише тут.

## Пріоритети при конфлікті

Якщо два правила суперечать одне одному, або незрозуміло, яке застосовувати:

1. **Hard-stops** (див. «Захищені дії»). Запит у чаті їх не скасовує — змінити можна лише редагуванням файлу правил.
2. Явний запит користувача в поточному повідомленні.
3. Загальні положення з цього файлу.
4. Специфічніше правило з підпапки за темою.

Для hard-stop **не питати дозволу**: відмовити і пояснити, яке правило забороняє дію і що треба змінити в `agents/`, щоб її дозволити.

**Якщо для рівнів 2–4 лишається сумнів — зупинись і запитай користувача.** Не обирай мовчки.

## Мова правил

Усі правила в `agents/` пишуться **українською**. Деталі — `agents/meta/writing-rules.md`.

## Роль репозиторію

iso-office — плагін Claude Code для десктопного застосунку. Панель **Office** показує сесії всіх проєктів: як ізометричний офіс (проєкт — кімната, сесія — працівник), як небо галактик (проєкт — галактика, сесія — зоря, кроки плану — планети) або без малюнка, лише списками. Сесії розкладено за станами (з помилкою, чекає рішення, потребує відповіді, у роботі, завершена тощо); клік відкриває акордеон з деталями чату. Що бачить користувач — `README.uk.md` / `README.md`.

- TypeScript без `package.json` і збірки: рушій Claude Code сам завантажує `hooks/register.tsx` (через `hooks/hooks.json`) і дає свій API (`claude-code`).
- Плагін **лише читає** файли Claude (список сесій, реєстр, транскрипти, власні записи застосунку) і пише один файл — `iso-office.json` з налаштуваннями.
- Працює лише у **Windows**: файли Claude читаються через `powershell`, чати відкриваються через `cmd /c start`.
- Користувач один — власник репозиторію. Коміти йдуть прямо в `main`. Зміни в панелі він бачить після перезавантаження плагінів або перезапуску Claude Desktop.

## Безпечні зони

Особливо обережно при змінах:

- PowerShell і `cmd`, що збираються з даних (`*Script()` у `hooks/detail.ts`, `hooks/errors.ts`, `hooks/sketch.ts`, `hooks/agents.ts`; `openChat` / `newSession` у `hooks/register.tsx`) — ін’єкція команд
- читання файлів Claude: обсяг (великі транскрипти), частота, поведінка, коли файлу немає чи формат змінився
- частота опитування й перемальовування (`POLL_MS`, TTL деталей, `steady()`) — навантаження і миготіння панелі
- атоми стану та їхній `shape`, кеш `SKETCH_VERSION` — збережений стан між запусками
- області кліку, виміряні в клітинках панелі
- запис `iso-office.json`

Для цих зон:

- пояснити ризик перед змінами
- уникати широких переписів
- надавати перевагу точковим/ізольованим змінам
- зберігати поведінку, якщо користувач не просив інакше
- включати кроки валідації
- не додавати нових команд ОС, мережевих викликів чи джерел даних без явної потреби

## Захищені дії

### Hard-stops — ніколи

Запит у чаті, «так», «apply» чи будь-яке інше підтвердження **не** дозволяють ці дії.

- Змінювати, видаляти чи створювати файли Claude: транскрипти й реєстр у теці Claude (`projects/`, `sessions/`), записи застосунку в `%LOCALAPPDATA%\Claude-Data` — ні кодом плагіна, ні командами під час розробки. Читати, щоб з’ясувати формат, можна — `agents/plugin/app-data-sources.md`.
- Переносити в репозиторій (тести, `docs/`, README, коміти) реальні дані з файлів Claude: назви чатів, тексти, шляхи, id сесій — `agents/typescript/tests.md`.
- Підставляти в PowerShell чи `cmd` значення, що не пройшло whitelist-перевірку — `agents/plugin/shell-scripts.md`.

### Лише за явним запитом

Не робити автоматично; дозволено, коли користувач явно попросив саме цю дію:

- коміт і push у `main` — `agents/workflow/commits-and-release.md`
- підняття версії в `.claude-plugin/plugin.json`
- нова команда ОС, мережевий виклик, нове джерело даних Claude, запис у новий файл
- зміна `.claude-plugin/marketplace.json` чи імені плагіна
- видалення файлів репозиторію

## Інженерний workflow

При зміні коду:

1. Знайти релевантні модулі (`agents/architecture/modules.md`) і наявні патерни.
2. Пояснити припущення, якщо задача неоднозначна; формат даних Claude невідомий — `agents/workflow/no-guesswork-without-data.md`.
3. Робити найменшу корисну зміну; логіку — у чисті функції з тестом.
4. Дотримуватись стилю, неймінгу й розподілу модулів.
5. Запустити тести й валідацію плагіна — `agents/workflow/validation-of-changes.md`.
6. Видима зміна — оновити обидва README — `agents/workflow/documentation.md`.
7. Підсумувати змінені файли і навіщо; назвати ризики й що перевірити в панелі після перезавантаження.

## Definition of done

Задача завершена, коли:

- виконано запит або аналіз
- переглянуто релевантні файли
- `claude plugin test .` і `claude plugin validate .` пройшли, або сказано, чому їх не запускали
- для видимої зміни названо, що перевірити в панелі після перезавантаження плагінів
- `README.md` і `README.uk.md` оновлено разом, якщо змінилась видима поведінка
- зафіксовано важливі припущення й ризики
